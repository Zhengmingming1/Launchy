## 完成记录（Done）

### 2026-10-28 · 报错文案：出问题时直接给「怎么修」按钮

- **改了什么**：
  - 「我的任务」扫描时会检查每个任务要打开的程序 / 脚本 / 文件还在不在（和残留项同一套规则：只有系统明确说「没有这个文件」才算丢了，没权限读取一律当作还在）。
  - 文件丢了的任务：状态标签显示橙色「找不到文件」，小字写「找不到「微信」了，可能被移走或删除，重新选一下就好」，后面跟一个「重新选择…」按钮，点了直接打开修改窗口。暂停中的任务也会提示，免得恢复后才发现跑不起来。
  - 上次运行失败的任务：失败原因后面跟一个「查看运行记录」按钮，不用再去找右键菜单。其他退出码的文案从「右键「查看运行记录」…」改成「运行记录里有详细信息」，配合按钮。
  - 修改任务窗口里，如果选中的文件已经不在了，路径框变成橙色边框，并在下面说明「找不到「xxx」了……请点「选择…」重新选一个」。不会阻止保存（例如外接硬盘暂时没插上时，用户可能只想改名字）。
  - VoiceOver：提示里会说「可在操作菜单中选择「重新选择」/「查看运行记录」」，文件丢了的任务操作菜单里多一项「重新选择」（只在需要时出现）。
- **为什么**：以前只告诉用户「出错了」，下一步该干什么要自己猜、还要知道去右键。普通用户最常见的问题就是「程序挪了位置 / 脚本被删了」，现在一眼看到原因，点一下就能修。
- **安全**：只多了一次只读的文件存在检查，只针对 Launchy 自己创建的任务；不改任何系统服务，苹果系统服务的安全规则没有变化。
- **参考**：[Homebrew/brew](https://github.com/Homebrew/brew)（`brew doctor` 的 `Library/Homebrew/diagnostic.rb`：每条检查不只说哪里有问题，还紧跟着告诉你该怎么修）。只借鉴想法，没有使用代码。
- **README / 截图**：README「我的任务」一节可以加一句「任务要打开的文件被移走时会提醒，并给出「重新选择」按钮」；`docs/images/mockup-my-tasks.png` 本来就要因 10-27 的改动重截，如果方便可以顺便放一个「找不到文件」的示例任务。

### 2026-10-27 · 新功能：「我的任务」显示上次运行结果

- **改了什么**：「我的任务」每一行的说明下面多了一行小字，说清楚这个任务跑得怎么样：
  - 「上次运行成功 · 本次启用以来运行了 3 次」；
  - 失败时用橙色写明原因，例如「上次运行失败：没能打开，要打开的程序或文件可能被移走或删除了」「脚本没有执行权限」「脚本里有找不到的命令」，其他退出码会提示右键「查看运行记录」；
  - 刚启用还没跑过时提示「还没运行过，右键「立即运行一次」可以先试试」；暂停的任务不显示。
  - 运行次数来自 `launchctl print gui/<uid>/<标签>` 里的 `runs = N`（`Launchctl.ServiceState` 新增 `runs` 字段），退出码继续用 `launchctl list`。VoiceOver 的提示里也会读出这一行。
- **为什么**：以前只有一个笼统的「出错了」标签，用户不知道任务到底有没有跑过、为什么失败，只能去翻日志。现在一眼就能确认「定时任务真的在跑」，失败了也知道大概该怎么改。
- **安全**：只读状态，不改任何任务或系统服务；系统服务的安全规则没有变化。
- **参考**：[jhuckaby/Cronicle](https://github.com/jhuckaby/Cronicle)（任务列表里直接显示每个任务最近一次运行的成功/失败和错误原因）。只借鉴想法，没有使用代码。
- **README / 截图**：README「我的任务」一节可以加一句「每个任务会显示上次运行成功还是失败，以及失败原因」；如果 docs/images 里有「我的任务」截图，周五发版时建议重新截图以体现新的小字。

### 2026-10-26 · 性能 / 体验：自启动目录有变化时自动刷新

- **改了什么**：新增 `DirectoryWatcher`，用系统的 DispatchSource 监听 `~/Library/LaunchAgents`、`/Library/LaunchAgents`、`/Library/LaunchDaemons` 三个文件夹。有软件新装、卸载或改了自启动项时，「开机自启动」列表会在约 0.6 秒后自动刷新：
  - 安装程序一次写好几个文件时会合并成一次刷新（防抖）；
  - 正在开关服务时不重复刷新（操作结束本来就会刷新）；
  - 文件夹一开始不存在（例如新电脑还没有 `~/Library/LaunchAgents`）也没关系，之后每次刷新都会补上监听；文件夹被删除或改名后也会重新挂上。
- **为什么**：以前开着 Launchy 去装/卸软件，列表不会变，用户得知道去点「刷新」。现在边装边看，新冒出来的自启动项、卸载后留下的残留项会直接出现。监听是事件驱动的，不轮询、不常驻线程，空闲时不占 CPU。
- **安全**：只监听、只读，不改任何文件；苹果 `/System/Library` 下的目录不监听（只读系统卷，平时不会变），系统服务的安全规则没有任何变化。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（PearcleanerSentinel 的 FileWatcher 监听废纸篓变化后自动提示）、[objective-see/BlockBlock](https://github.com/objective-see/BlockBlock)（监控持久化目录的思路）。只借鉴想法，没有使用代码。
- **README / 截图**：界面外观没有变化，无需更新截图；README「开机自启动」一节可以加一句「装或卸软件时列表会自动更新，不用手动刷新」。

### 2026-10-25 · 交互体验：开机自启动按状态筛选

- **改了什么**：「开机自启动」页列表上方加了分段筛选「全部 / 已开启 / 已停用 / 残留」，每段后面带数量（会跟着搜索词变化）：
  - 「残留」显示所有程序已被删除的项，关掉后仍留在列表里，方便确认已经处理过；
  - 顶部的残留提示条右边多了「只看残留项」按钮，一点就切到残留筛选；
  - 筛选结果为空时显示对应的话，比如「没有残留项，卸载得很干净。」。
- **为什么**：自启动项一多，用户要从长列表里自己找「哪些还开着」「我关过哪些」「哪些是残留」。现在一下就能分开看，清理残留也从「看到提示 → 自己翻列表」变成一步到位。
- **安全**：只改显示，不改任何开关逻辑；系统服务页不受影响。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（Homebrew 页面顶部用分段控件切换不同视图）。只借鉴想法，没有使用代码。
- **README / 截图**：`docs/images/mockup-startup.png` 里没有筛选条，周五发版时建议重新截图；README「开机自启动」一节可以加一句「可以按 已开启 / 已停用 / 残留 筛选」。

### 2026-10-24 · 无障碍：列表行支持 VoiceOver

- **改了什么**：三个页面共用的列表行（ItemRow）对 VoiceOver 合并成一个元素：
  - 读成一句「名字，状态」，开关状态作为值读出（开启/关闭），说明文字放在提示里；
  - 状态里的 ⚠️、🔒 表情不再被念成「警告符号」「锁」之类的噪音；
  - 「操作」菜单（VO+Command+空格）里可以直接切换开关；开关不可用时会说明原因；
  - 「开机自启动」「系统服务」的行标记为按钮，按下即打开详情；「在访达中显示」以及我的任务的「修改 / 立即运行一次 / 查看运行记录 / 删除」等原本只在右键菜单里的功能，也加进了 VoiceOver 操作菜单。
- **为什么**：以前每行会被拆成好几块（图标、名字、状态、无名开关）逐个念，开关没有名字，单击打开详情和右键菜单对读屏用户也基本用不了。
- **安全**：没有改动任何开关逻辑；开关被禁用时（例如系统服务未开高级模式）VoiceOver 的切换操作同样不会生效。
- **参考**：[p0deje/Maccy](https://github.com/p0deje/Maccy)（剪贴板历史行用 `accessibilityAction(named:)` 提供置顶、删除等操作）。只借鉴想法，没有使用代码。
- **README / 截图**：界面外观没有变化，无需更新截图；README 可以在特色里加一句「支持 VoiceOver 读屏」。

### 2026-10-22 · 新功能 / 安全体验：标出「残留」自启动项

- **改了什么**：扫描第三方自启动项时检查 plist 里写的程序文件是否还在。程序已被删除的项：
  - 列表状态显示橙色「⚠️ 程序已删除」；
  - 「开机自启动」页顶部出现提示条：「发现 N 个残留项……可以放心关掉」；
  - 详情页顶部用大白话说明原因和处理方法（关掉，或在访达中把配置文件移到废纸篓）。
- **为什么**：软件卸载后经常只删了 .app，留下 LaunchAgent/Daemon，开机时反复报错、拖慢登录。普通用户看不出哪些能关，现在一眼就知道。
- **安全**：只检查第三方服务，苹果 `/System/Library` 下的服务完全不参与；只认绝对路径，且只有系统明确返回「文件不存在」（ENOENT/ENOTDIR）才标记，没权限读取一律当作存在，宁可漏报不误报；不自动删除任何东西。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（孤立文件 / 残留文件搜索的思路）、[objective-see/KnockKnock](https://github.com/objective-see/KnockKnock)（列出持久化项并标出可疑项）。只借鉴想法，没有使用代码。
- **README / 截图**：README「开机自启动」一节可以加一句「会标出软件卸载后留下的残留项」；`docs/images/mockup-startup.png` 没有体现残留提示条，周五发版时可以顺手更新。
