### 2026-11-23 · 逻辑 / 健壮性：切换「分钟 / 小时」时，间隔数字一起换算

- **改了什么**（`TaskEditorView`、`TaskSchedule.convertInterval`）：
  - 新建任务时「每隔」默认是 60 分钟。以前把单位切到「小时」，数字不变，就成了「每隔 60 小时」（两天半才跑一次），很容易没注意就保存了。现在切换单位时会一起换算：60 分钟 → 1 小时，2 小时 → 120 分钟，实际间隔不变。
  - 不是整小时的（例如 90 分钟）切到小时会四舍五入成 2 小时，并在下面用灰色小字说一句「90 分钟不是整小时，已按 2 小时算……」；再改数字或切回分钟，这句话就消失。
  - 不到 60 分钟的数字切到小时时原样保留（多半是用户先填了数字、正要选「小时」）。数字是 0 或空时不动，原来的「间隔要大于 0」提示照常工作。
  - 换算放在一个单独的小函数里，大数字不会溢出崩溃。
- **为什么**：普通用户通常先点单位再改数字，或者根本不看数字。「60 小时」这种意外值不会报错，只会让任务看起来「一直没运行」，很难自己找到原因。
- **安全**：只改编辑窗口里数字的换算，保存格式、launchd 配置和已有任务都没变；苹果系统服务的安全规则没有变化。
- **参考**：[newmarcel/KeepingYouAwake](https://github.com/newmarcel/KeepingYouAwake)（7k+ star 的菜单栏小工具，「添加时长」窗口把时长当成一个整体的时间来存，默认 1 小时，并把超出范围的小时 / 分钟数自动收回到合理值）。只借鉴「单位只是显示方式，实际时长保持一致、意外值自动纠正」的想法，没有使用代码（MIT 许可，本身可兼容，仍自己写）。
- **提交**：与本次改动同一提交（未在真机上测试）
- **README / 截图**：界面外观基本没变（只在四舍五入时多一行灰色小字），不用重截图；README 不必改，发版说明里可以写一句「切换分钟 / 小时时，间隔会自动换算」。

- **改了什么**（`ServiceDetailView` / `ServiceEditView`、`RestoreCleanupView`）：

### 2026-11-21 · 功能：误清理的残留配置，可以在本软件里从备份还原

- **改了什么**（ServiceEditor / OrphanCleanup、ServicesStore、StartupView、RestoreCleanupView）：
  - 清理残留项时，除了把配置文件复制到备份目录，还会写下原来的路径和名称（和备份成对的一份说明）。编辑服务时的备份不会出现在这个还原列表里。
  - 「开机自启动」页在有可还原的备份时，出现一条灰色提示和「从备份还原…」按钮；在「残留」筛选已经空了、但仍有备份时，空列表也会提示可以用上面的按钮。
  - 还原前要确认。只会把配置文件放回原来的位置，不会自动开启；如果那个程序还没装回来，它仍会显示为残留项。涉及 /Library 时可能要一次登录密码。原位置已经有文件时不会覆盖。
  - 只允许还原到用户或系统的 LaunchAgents、LaunchDaemons 目录里的一份 plist，不会写到苹果系统目录或其他位置。启动台助手自己的任务也不会从这里还原。
  - 本版本之前清理的项如果当时没有留下这份说明，列表里不会出现；仍可以到废纸篓里找。
- **为什么**：清理之后这一项从列表里消失了，详情页的「从备份恢复」也就进不去。文案里虽然说可以从废纸篓或备份找回来，但软件里没有入口。误清理时，普通用户很难自己把配置放回原处。
- **安全**：还原前当场再检查备份内容和目标路径；不自动加载或开启服务；不覆盖已有文件；拒绝系统路径和本软件自己的任务。苹果系统服务的安全规则没有变化。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner) 的 Undo Manager / Delete History（清理后可以在软件里还原，并且校验路径、避免动到系统目录）。只借鉴「清理后可在软件里还原、并校验路径」的想法，没有使用代码。
- **提交**：与本次改动同一提交（未在真机上测试）

### 2026-10-26 · 性能 / 体验：自启动目录有变化时自动刷新

- **改了什么**：新增 `DirectoryWatcher`，用系统的 DispatchSource 监听 `~/Library/LaunchAgents`、`/Library/LaunchAgents`、`/Library/LaunchDaemons` 三个文件夹。有软件新装、卸载或改了自启动项时，「开机自启动」列表会在约 0.6 秒后自动刷新：
  - 安装程序一次写好几个文件时会合并成一次刷新（防抖）；
  - 正在开关服务时不重复刷新（操作结束本来就会刷新）；
  - 文件夹一开始不存在（例如新电脑还没有 `~/Library/LaunchAgents`）也没关系，之后每次刷新都会补上监听；文件夹被删除或改名后也会重新挂上。
- **为什么**：以前开着 Launchy 去装/卸软件，列表不会变，用户得知道去点「刷新」。现在边装边看，新冒出来的自启动项、卸载后留下的残留项会直接出现。监听是事件驱动的，不轮询、不常驻线程，空闲时不占 CPU。
- **安全**：只监听、只读，不改任何文件；苹果 `/System/Library` 下的目录不监听（只读系统卷，平时不会变），系统服务的安全规则没有任何变化。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（PearcleanerSentinel 的 FileWatcher 监听废纸篓变化后自动提示）、[objective-see/BlockBlock](https://github.com/objective-see/BlockBlock)（监控持久化目录的思路）。只借鉴想法，没有使用代码。
- **README / 截图**：界面外观没有变化，无需更新截图；README「开机自启动」一节可以加一句「装或卸软件时列表会自动更新，不用手动刷新」。
