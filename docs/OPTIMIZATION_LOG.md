### 2026-10-31 · 报错文案：失败原因直接说出「哪条命令、哪个文件」

- **改了什么**：
  - 新增 `LogDiagnosis`：任务上次运行失败（退出码 1–127）时，只读运行记录末尾 4 KB、最后 20 行，从后往前找第一条认识的错误，把「上次运行失败：」后面的原因换成具体的一句话：
    - `command not found`：「脚本第 12 行的命令「ffmpeg」找不到……」。如果这个命令其实装在 `/opt/homebrew/bin`、`/usr/local/bin` 等地方（launchd 默认的 PATH 里没有它们，这是定时脚本最常见的坑），直接告诉用户「把它改成完整路径 /opt/homebrew/bin/ffmpeg 就行」；
    - `permission denied`：「没有权限打开「x.sh」……」；
    - `no such file or directory` / `The file … does not exist.`：「找不到「Backup」，它可能被移走、改名或删除了」；
    - `Operation not permitted`：说明是 macOS 隐私保护拦住了，并指到「完全磁盘访问权限」；
    - `open -a` 报 `Unable to find application named`：「找不到程序「xxx」……」。
  - 认不出来、被信号强制结束、或文件已经找不到（已有「重新选择…」）时，照旧按退出码解释，不会乱猜。「查看运行记录」按钮保持不变。
- **为什么**：以前只能说「脚本里有找不到的命令」「退出码 1」，用户还得自己翻日志、看懂英文。现在一眼就知道是哪一行、哪个命令或文件，Homebrew 命令的情况还直接给出改法。
- **性能 / 安全**：只有失败的任务才读日志，而且只读末尾几 KB；纯只读，不改脚本、不改任何系统服务，苹果系统服务的安全规则没有变化。
- **参考**：[nvbn/thefuck](https://github.com/nvbn/thefuck)（按规则匹配命令的错误输出，如 `no_command`、`permission_denied`，然后给出具体修正建议）。只借鉴「匹配错误输出 → 给出具体建议」的想法，没有使用代码。
- **README / 截图**：界面布局没变，无需重截；README「我的任务」一节可以加一句「任务失败时会读运行记录，直接说出是哪条命令或哪个文件出了问题」。

### 2026-10-30 · 逻辑 / 健壮性：「我的任务」自动保持最新

- **改了什么**：
  - `MyTasksStore` 复用 `DirectoryWatcher` 监听 `~/Library/LaunchAgents`：用户在访达里删掉任务文件、或用别的工具改了 Launchy 的任务时，列表约 0.6 秒后自动更新；文件夹一开始不存在时，建好第一个任务后自动补上监听。
  - 切回 Launchy 窗口时自动刷新一次（最多每 3 秒一次，来回切窗口不会反复扫描）。任务在后台跑完后，「上次运行成功 / 失败」「运行了几次」以及侧栏的橙色感叹号，用户回到 Launchy 时就已经是最新的，不用再点「刷新」。
  - 扫描加了「代数」判断：连续触发多次刷新时只采用最后一次的结果，避免列表短暂闪回旧状态；结果和当前一样时不重新赋值，减少无谓重绘。
- **为什么**：前几天加的「上次运行结果」「找不到文件」「侧栏提醒」都依赖扫描结果，但以前「我的任务」只在启动和操作后刷新。普通用户开着 Launchy 等任务跑完，看到的却是旧状态，容易以为任务没跑。
- **安全**：只读扫描，监听事件驱动、不轮询；只监听用户自己的 `~/Library/LaunchAgents`，不改任何文件，苹果系统服务的安全规则没有变化。
- **参考**：[Ranchero-Software/NetNewsWire](https://github.com/Ranchero-Software/NetNewsWire)（`AccountNotificationInspectorView` 在 App 回到前台 `didBecomeActive` 时重新检查状态）、[exelban/stats](https://github.com/exelban/stats)（传感器面板在 App 激活时重查辅助程序状态）。只借鉴想法，没有使用代码。
- **README / 截图**：界面外观没有变化，无需更新截图；README「我的任务」一节可以加一句「任务跑完后切回 Launchy 就能看到最新结果，不用手动刷新」。

### 2026-10-26 · 性能 / 体验：自启动目录有变化时自动刷新

- **改了什么**：新增 `DirectoryWatcher`，用系统的 DispatchSource 监听 `~/Library/LaunchAgents`、`/Library/LaunchAgents`、`/Library/LaunchDaemons` 三个文件夹。有软件新装、卸载或改了自启动项时，「开机自启动」列表会在约 0.6 秒后自动刷新：
  - 安装程序一次写好几个文件时会合并成一次刷新（防抖）；
  - 正在开关服务时不重复刷新（操作结束本来就会刷新）；
  - 文件夹一开始不存在（例如新电脑还没有 `~/Library/LaunchAgents`）也没关系，之后每次刷新都会补上监听；文件夹被删除或改名后也会重新挂上。
- **为什么**：以前开着 Launchy 去装/卸软件，列表不会变，用户得知道去点「刷新」。现在边装边看，新冒出来的自启动项、卸载后留下的残留项会直接出现。监听是事件驱动的，不轮询、不常驻线程，空闲时不占 CPU。
- **安全**：只监听、只读，不改任何文件；苹果 `/System/Library` 下的目录不监听（只读系统卷，平时不会变），系统服务的安全规则没有任何变化。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（PearcleanerSentinel 的 FileWatcher 监听废纸篓变化后自动提示）、[objective-see/BlockBlock](https://github.com/objective-see/BlockBlock)（监控持久化目录的思路）。只借鉴想法，没有使用代码。
- **README / 截图**：界面外观没有变化，无需更新截图；README「开机自启动」一节可以加一句「装或卸软件时列表会自动更新，不用手动刷新」。

### 2026-10-22 · 新功能 / 安全体验：标出「残留」自启动项

- **改了什么**：扫描第三方自启动项时检查 plist 里写的程序文件是否还在。程序已被删除的项：
  - 列表状态显示橙色「⚠️ 程序已删除」；
  - 「开机自启动」页顶部出现提示条：「发现 N 个残留项……可以放心关掉」；
  - 详情页顶部用大白话说明原因和处理方法（关掉，或在访达中把配置文件移到废纸篓）。
- **为什么**：软件卸载后经常只删了 .app，留下 LaunchAgent/Daemon，开机时反复报错、拖慢登录。普通用户看不出哪些能关，现在一眼就知道。
- **安全**：只检查第三方服务，苹果 `/System/Library` 下的服务完全不参与；只认绝对路径，且只有系统明确返回「文件不存在」（ENOENT/ENOTDIR）才标记，没权限读取一律当作存在，宁可漏报不误报；不自动删除任何东西。
- **参考**：[alienator88/Pearcleaner](https://github.com/alienator88/Pearcleaner)（孤立文件 / 残留文件搜索的思路）、[objective-see/KnockKnock](https://github.com/objective-see/KnockKnock)（列出持久化项并标出可疑项）。只借鉴想法，没有使用代码。
